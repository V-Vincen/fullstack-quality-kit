# SQL 与索引性能子清单

适用范围：SQL、Mapper、索引、查询、批量写入和分页变化。

## 查询语义与正确性

- [ ] 查询条件、连接条件、排序字段和返回字段是否符合业务语义。
- [ ] 左连接、内连接、外连接是否正确；重复行、去重是否符合预期。
- [ ] 空值处理是否明确（WHERE a IS NULL vs WHERE a = NULL）。
- [ ] 分组、聚合、子查询的逻辑是否正确；GROUP BY 是否包含所有非聚合字段。

## 索引使用与执行计划

- [ ] 执行计划显示是否命中索引，还是全表扫描或全索引扫描。
- [ ] 索引字段顺序是否与过滤、排序、连接条件匹配（最左前缀原则）。
- [ ] 检查是否存在函数包列、类型转换导致索引失效（如 WHERE DATE(created_at) = ?）。
- [ ] 隐式类型转换（字符串与数字比较）是否导致索引无法使用。

## 查询性能与分析

- [ ] 性能问题基于真实数据量、执行计划（EXPLAIN）和基线对比，不凭单条数据推断。
- [ ] 查询响应时间、返回行数、扫描行数（rows examined）和 I/O 成本。
- [ ] 复杂查询（多表连接、子查询）是否拆分、改写或使用中间表优化。
- [ ] 深分页（LIMIT 100000, 20）是否使用游标分页或倒序扫描优化。

## 分页与排序稳定性

- [ ] 分页排序是否稳定，避免并发写入下的漏数据或重复数据。
- [ ] 空页面（LIMIT 100000, 20 超过总行数）的处理。
- [ ] 游标分页（WHERE id > last_id LIMIT 20）相比 OFFSET 的优势。
- [ ] 并发写入下的分页一致性是否需要快照隔离或版本控制。

## 索引设计与维护

- [ ] 组合索引顺序：选择性最高的字段优先（不一定是 WHERE 字段顺序）。
- [ ] 覆盖索引设计：查询所需字段都在索引中，避免回表。
- [ ] 索引字段数量不过多（通常 3-5 个字段）；列举候选索引并评估成本。
- [ ] 唯一索引是否有必要；重复索引是否应合并或删除。
- [ ] 新增索引的维护成本（写入放大、空间成本、构建时间）是否可接受。

## 批量操作与性能

- [ ] 批量查询控制批次大小和内存占用；避免一次加载所有数据。
- [ ] 批量插入、更新使用 BATCH 模式或多值 INSERT；检查是否超过 max_allowed_packet。
- [ ] 避免循环内逐条查询（N+1）；使用 IN 子句或左连接。
- [ ] 批量删除分批操作；避免单次锁表或事务过大。

## 连接与 JOIN 优化

- [ ] 连接顺序是否驱动表正确；通常小表或过滤条件多的表作为驱动表。
- [ ] 连接条件是否走索引；避免非主键字段连接导致全表扫描。
- [ ] 连接表数量过多（>4 个表）时考虑拆分或使用中间表。
- [ ] 左连接导致的聚合结果行数增加是否符合预期。

## 聚合与子查询

- [ ] GROUP BY 性能是否可接受；大表分组可能需要索引支撑或物化视图。
- [ ] HAVING 过滤条件是否在 GROUP BY 后才应用，影响行数。
- [ ] 子查询是否转换为 IN 或 EXISTS；相关子查询的性能开销。
- [ ] UNION 与 UNION ALL 的选择；DISTINCT 的性能成本。

## 并发写入与锁

- [ ] 批量更新是否因行锁升级导致表锁，影响其他连接。
- [ ] 批量插入的目标表是否有唯一约束冲突；回滚成本是否可控。
- [ ] 外键约束是否在高并发写入时导致锁等待或死锁。

## 常见陷阱与交叉参考

- [ ] 避免使用 SELECT * 导致列增加后自动获取不需要的字段。
- [ ] 避免在 WHERE 条件中使用 OR 而导致无法使用组合索引。
- [ ] 避免在索引字段上使用函数；优先改写查询条件。
- [ ] 避免隐式转换；使用明确的类型转换或参数绑定。
- [ ] 参考 schema-definition.md 的索引设计原则。
- [ ] 参考 database-quality.md 的执行计划分析和性能工具使用。
