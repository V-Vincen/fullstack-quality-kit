# Java 质量子清单

适用范围：Java 源码、Java 配置、公共模型和 Java 测试代码。

## 命名与代码规范

- [ ] 按项目采用的 Alibaba Java Coding Guidelines 版本检查类、方法、变量和常量命名。
- [ ] 类名、接口名、枚举名和内部类命名遵循驼峰规范和明确语义。
- [ ] 常量使用大写下划线分隔，变量和方法使用小写驼峰。
- [ ] 避免单字母变量名（除循环计数器），避免与 Java 关键词或库类名重名。
- [ ] 方法职责单一，避免超大方法；参数过多时考虑引入参数对象或 Builder。

## 对象相等与哈希

- [ ] 实现 `equals` 时必须同时实现 `hashCode`，保持一致性。
- [ ] `equals` 检查类型、空值、所有关键字段；不能只比较某个字段。
- [ ] 可变对象作为 Map key 时检查是否会变更，导致数据丢失或重复。
- [ ] 比较器实现是否满足传递性、自反性和一致性；排序是否稳定。

## 类型转换与精度

- [ ] 类型转换（int to long、float to double）是否明确和必要。
- [ ] 数值精度、金额类型使用 BigDecimal 而非 double，避免丢失或舍入错误。
- [ ] 时间戳单位一致（秒、毫秒、纳秒），时区转换是否正确。
- [ ] 字符编码、字符集转换是否指定编码，避免平台依赖。

## 集合与性能

- [ ] 集合初始化时是否指定容量，避免不必要的扩容。
- [ ] 嵌套循环、多层迭代的复杂度是否可接受；大批量操作是否考虑流式处理或批处理。
- [ ] 装箱拆箱频繁发生时是否考虑使用原始类型集合库（IntList、LongSet）。
- [ ] 集合不必要的复制、序列化、反序列化是否频繁发生。
- [ ] 集合的 contains、remove 操作的时间复杂度是否符合使用场景。

## 并发与线程安全

- [ ] 共享状态、可见性、内存屏障和 volatile 使用是否正确。
- [ ] 锁顺序一致，避免死锁；同步块范围尽可能小。
- [ ] 使用线程安全集合（ConcurrentHashMap）还是外部同步取决于实际场景。
- [ ] 异步异常、Future 的 get 超时、CompletableFuture 链式调用是否正确处理。
- [ ] 共享字段、静态变量、单例的初始化是否线程安全。

## 线程池与异步

- [ ] 线程池大小、队列、拒绝策略和命名是否合理。
- [ ] 异步任务的异常是否被捕获和日志记录，避免后台异常无法定位。
- [ ] submit 和 execute 的返回值是否正确处理（Future.get、异常捕获）。
- [ ] 线程池关闭流程是否明确，是否 await 完成或超时强制关闭。
- [ ] 阻塞调用（sleep、wait、take）是否可能导致线程饥荒或死锁。

## 资源与生命周期

- [ ] 流、文件、Socket、HTTP 连接、数据库连接和 ResultSet 的生命周期是否明确。
- [ ] try-with-resources 或 try-finally 关闭资源；异常路径也能释放。
- [ ] 监听器、定时器、Observer 和订阅在不需要时正确移除。
- [ ] 静态集合、缓存和全局对象是否可能无限增长。

## 性能与基准

- [ ] 性能或 JVM 结论必须关联复杂度分析（时间 O(n)、空间 O(1)）。
- [ ] 优化结论基于实际基准、运行日志、堆转储或线程转储证据。
- [ ] 不凭直觉推测，必须用实际数据或工具验证（JMH、YourKit、MAT）。
- [ ] GC 压力、内存泄漏和锁竞争的判断需要日志或分析工具支撑。

## 常见陷阱与交叉参考

- [ ] 避免在 catch 块中进行昂贵操作（数据库、网络）；异常不应该当流程控制。
- [ ] Integer/Long 缓存（-128 到 127），比较应使用 equals 而非 ==。
- [ ] String 拼接使用 StringBuilder，避免循环内 + 导致二次方复杂度。
- [ ] 参考 code-quality-baseline.md 的异常处理、资源管理和日志要求。
- [ ] Spring Boot 代码参考 springboot-quality.md 的 Bean 生命周期和配置。
