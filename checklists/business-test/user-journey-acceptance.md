# 用户流程验收子清单

适用范围：核心用户流程、关键页面、注册登录、提交申请、下单付款或用户明确要求体验验收的任务。

## 场景定义与准备

- [ ] 明确目标用户角色、核心任务目标和业务价值。
- [ ] 列出从正常入口到完成目标所需的全部步骤。
- [ ] 确认测试环境、测试账号、测试数据和未覆盖的场景范围。
- [ ] 预期耗时、关键转化点和用户放弃风险点。

## 正常流程验收

- [ ] 从普通用户可见的正常入口完成任务，不使用内部地址、源码、隐藏接口或开发者知识绕过。
- [ ] 每个步骤验证用户能否理解当前目标和发现正确入口。
- [ ] 操作反馈是否及时、清晰（成功提示、失败原因、加载进度）。
- [ ] 用户是否知道下一步、可选操作和返回选项。
- [ ] 核心流程耗时是否可接受，是否有明显卡顿或阻塞。

## 页面与交互验收

- [ ] 结合实际浏览器渲染检查文字、控件、状态反馈和布局。
- [ ] 验收不能只凭自动化点击成功判定通过，需要视觉确认和人工交互。
- [ ] 桌面端、移动端或目标浏览器（Chrome、Safari、微信内置浏览器）表现是否符合预期。
- [ ] 响应式设计在不同屏幕尺寸下是否完整（横屏、竖屏、缩放）。
- [ ] 文字、图标、颜色和强调是否能被用户正确理解。

## 状态与反馈

- [ ] 加载中、成功、失败、空数据、权限不足、超时等状态是否有明确反馈。
- [ ] 错误提示是否清晰说明问题原因和解决方向（不只是"操作失败"）。
- [ ] 进度指示、预期时间和取消选项是否完整。
- [ ] 提交后的确认、撤销或修改选项是否清楚。

## 跨浏览器与设备兼容

- [ ] 在项目支持的目标浏览器（IE 11、Chrome、Firefox、Safari 等）测试。
- [ ] 移动设备触摸交互、输入法、虚拟键盘是否影响页面布局。
- [ ] 网络状态变化（从 WiFi 切换到 4G，或离线）时的表现。
- [ ] 浏览器缩放（150%、200%）和字体放大的表现。

## 问题分类与记录

- [ ] 区分功能故障（实现有误）、体验障碍（用户不理解）和视觉偏好（样式个人喜好）。
- [ ] 每个问题记录：复现路径、截图或日志、用户影响程度、最小改进方向。
- [ ] 阻塞问题（无法完成流程）、严重问题（功能错误）、中等问题（易出错）、轻微问题（美观）分别标记。
- [ ] 功能故障需提供技术细节（对应代码、接口、错误日志）。

## 授权与数据安全

- [ ] 只使用已授权的测试环境、账号和测试数据。
- [ ] 真实付款前必须停止并等待额外授权；不能在测试中发起真实交易。
- [ ] 对外发送（邮件、短信、推送）、发布（上线、分享）或修改真实业务数据前停止。
- [ ] 测试完成后清理测试数据和临时修改。

## 回归与验证

- [ ] 验证通过的问题修复后，重新走通完整流程。
- [ ] 修复过程中是否意外影响其他流程或相关功能。
- [ ] 边界场景（空列表、最后一项、超长内容）的表现。

## 输出与报告

- [ ] 报告通过项、问题项、未验证范围、验证边界和已知风险。
- [ ] 列出验证涉及的环境、账号、测试数据和测试工具。
- [ ] 对无法在当前环境验证的场景（支付、发送、审核）标记为"待确认"。
- [ ] 建议是否需要长期回归测试或自动化验收测试。
