# Markdown 排版规范

## 适用范围

本规范适用于仓库内全部 Markdown 文档，包括：

- README 和变更记录。
- AGENTS.md 和规则片段。
- docs/ 目录下的说明文档。
- .codex/checklists/ 下的总清单和领域子清单。
- .codex/skills/ 下的 skill 文档。

本规范只约束排版和文档结构，不改变规则含义、skill 路由、清单检查项、命令参数或脚本行为。

## 标题层级

- 每个文档最多使用一个一级标题。
- 一级标题使用 `#`，表示文档名称。
- 二级标题使用 `##`，表示主要章节。
- 三级标题使用 `###`，表示平台、场景或具体子项。
- 标题层级不得跳级。
- 标题前后各保留一个空行。
- 标题末尾不使用句号或冒号。

推荐结构：

~~~text
# 文档标题

简要说明。

## 主要章节

章节说明。

### 具体场景

场景说明。
~~~

## 段落和空行

- 标题、段落、列表、表格和代码块之间保留一个空行。
- 连续段落之间保留一个空行。
- 不使用连续多个空行制造视觉间距。
- 每个段落表达一个完整意思，避免将多个主题挤在同一段中。

## 代码和命令

- 行内命令、文件名、目录和配置项使用反引号，例如 `validate.sh`。
- 独立命令使用代码块。
- 代码块统一使用三个波浪号，并标明语言，例如 `~~~bash`。
- 命令块中的内容必须可以直接复制执行。
- 代码块前后各保留一个空行。
- 不在命令块中混入解释性文字。

常用语言标识：

| 内容 | 标识 |
|---|---|
| Bash 命令 | bash |
| PowerShell 命令 | powershell |
| Windows 批处理 | bat |
| 普通目录结构或文本 | text |
| Markdown 示例 | markdown |

## 列表和检查项

- 普通无序列表统一使用 `-`。
- 有执行顺序的内容使用数字列表。
- 嵌套列表统一缩进两个空格。
- 列表前后各保留一个空行。
- 每个列表项尽量只表达一个事项。
- 检查项统一使用 `- [ ]` 和 `- [x]`。
- 不适用的检查项应写明“不适用”和原因。

## 表格

表格统一使用标准 Markdown 格式，包含表头、分隔线和数据行。

规则：

- 第一行为表头。
- 第二行为分隔线。
- 列名保持简短。
- 表格内容较长或包含复杂说明时，改用列表。
- 表格中的路径、命令和配置项使用反引号。

## 平台和场景

同一功能包含多个平台或场景时，使用统一的三级标题：

- macOS/Linux
- Windows PowerShell
- Windows 命令提示符

平台标题不使用普通段落，也不在标题后添加冒号。每个平台按照“说明文字 → 命令块”的顺序编排。

## 链接和图片

- 仓库内部文档使用相对路径链接。
- 外部资料使用完整 HTTPS 链接。
- 链接文字应说明目标内容，不使用“点击这里”。
- 图片必须提供有意义的替代文本。
- 图片路径优先使用仓库内相对路径。

## 文档类型

| 文档类型 | 建议结构 |
|---|---|
| README.md | 项目简介、当前状态、目录结构、快速使用、限制 |
| docs/*.md | 适用场景、前置条件、操作步骤、验证、回滚和限制 |
| 总清单 | 适用范围、触发条件、领域路由、检查项、结果要求 |
| 领域子清单 | 标题、适用范围、专项检查项 |
| SKILL.md | 元数据、目标、流程、路由、输出要求和边界 |
| AGENTS.md | 索引、职责、规则、授权、验证和交付 |
| CHANGELOG.md | 版本或阶段、变更内容、限制和验证状态 |

## 语言和标识

- 正文默认使用简体中文。
- 命令、路径、文件名、产品名、API 名称和 skill 名称保留原文。
- 技术标识只在确有必要时使用，不堆砌无关英文。
- 文档中的路径、命令和配置项使用反引号标识。

## 交付前检查

- 标题层级连续且风格统一。
- 平台和场景均使用统一的三级标题。
- 代码块成对并标明语言。
- 列表、表格和代码块前后有空行。
- 内部链接和文件路径真实有效。
- 命令可以直接复制，且没有混入解释文字。
- 没有重复、过期或相互矛盾的说明。
- 已明确验证结果、未覆盖项和已知风险。
