# 数据库变更清单

适用范围：执行数据写入、删除、结构变更或可能造成锁等待的数据库操作前后执行。

## 清单路径解析

CHECKLIST_ROOT 先解析为当前项目/.codex/checklists/；不存在时再解析为 ~/.codex/checklists/fullstack-quality-kit/。以下路由均相对于 CHECKLIST_ROOT。

## 领域子清单路由

根据数据库变更类型继续读取：

- 表结构：`CHECKLIST_ROOT/db-change/schema-definition.md`
- SQL 与索引：`CHECKLIST_ROOT/db-change/sql-index-performance.md`
- 数据迁移：`CHECKLIST_ROOT/db-change/migration-compatibility.md`
- 事务与锁：`CHECKLIST_ROOT/db-change/transaction-lock.md`
- 回滚与恢复：`CHECKLIST_ROOT/db-change/rollback-recovery.md`
- 数据结果验证：`CHECKLIST_ROOT/db-change/data-result-verification.md`

总清单负责执行前、中、后的共同门禁，领域子清单负责具体变更类型；未执行的子清单必须明确标记。

## 执行前

- [ ] 明确目标环境、数据库、表、数据范围和影响对象。
- [ ] 只读查询先确认现状；生产环境默认只读，实际写入必须获得明确授权。
- [ ] 保存变更前数据或结构信息，避免依靠记忆恢复。
- [ ] 检查 SQL 文件头部是否说明目标数据库、模式、表、执行前提、变更对象、业务目的、历史数据处理方式、重复执行语义、事务或锁影响、失败处理和回滚脚本。
- [ ] 检查新增或调整字段是否有字段注释；新建表必须为表内全部字段写明字段注释。因数据库能力、第三方对象等无法添加时，记录原因。
- [ ] 确认脚本没有夹带未授权的 OWNER、权限、数据迁移或其他额外变更；发现超出范围立即停止。
- [ ] 为 `INSERT`、`UPDATE`、`DELETE`、`ALTER` 等操作准备可执行的回滚 SQL。
- [ ] 检查目标表是否存在活跃事务、长事务或其他锁持有者。
- [ ] 可能获取排他锁时设置短 `lock_timeout`，禁止无限等待。
- [ ] 确认执行窗口、事务边界、批量大小和失败处理方式。

## 执行中

- [ ] 先小范围或事务内验证，再扩大执行范围。
- [ ] 监控锁等待、影响行数和异常信息；发现阻塞或异常立即停止并按回滚方案处理。
- [ ] 不使用硬编码主键或未经核对的条件覆盖其他业务数据。

## 执行后

- [ ] 核对影响行数、关键字段、唯一约束、关联表和业务状态。
- [ ] 对新增或调整的表、字段、索引和约束逐项核对实际数据库结构，确认与脚本和需求一致。
- [ ] 必要时用业务查询或页面交叉验证，而不只看 SQL 执行成功。
- [ ] 记录实际执行的数据库、脚本、命令、影响结果、剩余风险和回滚是否可用；未执行的脚本必须明确标记。
