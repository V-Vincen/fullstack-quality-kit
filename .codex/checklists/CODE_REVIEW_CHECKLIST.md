# 代码审查清单

适用范围：代码、配置或脚本发生写入后执行。每项都要有实际检查证据；不相关项标记为“不适用”并说明原因。

## 清单路径解析

CHECKLIST_ROOT 先解析为当前项目/.codex/checklists/；不存在时再解析为 ~/.codex/checklists/fullstack-quality-kit/。以下路由均相对于 CHECKLIST_ROOT。

## 领域子清单路由

根据修改范围继续读取：

- 通用代码质量：`CHECKLIST_ROOT/code-review/code-quality-baseline.md`
- Java：`CHECKLIST_ROOT/code-review/java-quality.md`
- Spring Boot：`CHECKLIST_ROOT/code-review/springboot-quality.md`
- 数据库：`CHECKLIST_ROOT/code-review/database-quality.md`
- 数据访问层：`CHECKLIST_ROOT/code-review/data-access-quality.md`
- 前端：`CHECKLIST_ROOT/code-review/frontend-quality.md`
- 安全代码：`CHECKLIST_ROOT/code-review/security-code-quality.md`
- 测试代码：`CHECKLIST_ROOT/code-review/test-code-quality.md`

总清单负责通用门禁，领域子清单负责技术专项；不要把未涉及的技术领域标记为已检查。

## 变更范围

- [ ] 检查 `git status` 和 `git diff --stat`，确认所有改动文件。
- [ ] 对每个修改文件提供一个可点击的首个修改点链接，格式为 `[项目相对路径/文件名](/绝对路径/文件名:72)`；应用会根据链接目标中的 `:行号` 自动显示行号，链接文字和链接外不得再写 `line`、`第 N 行` 或其他行号，也不使用代码标记包裹链接文字。同一文件其他修改不再逐行列出，多个文件分别记录各自的首个修改点。
- [ ] 确认改动文件确实被调用：追溯路由、父组件、服务入口和关键参数。
- [ ] 对比修改前状态，确认没有覆盖或删除用户原有未提交改动。
- [ ] 对每个发现的问题记录触发场景、证据、根因、影响、修改建议、处理状态、验证结果和未处理风险，不能只记录错误现象。

## 代码正确性

- [ ] 检查 `null`、空集合、默认值、边界值和重复调用。
- [ ] 检查异常类型、异常转换和对外错误信息，不能暴露堆栈或 SQL。
- [ ] 检查 SQL、Mapper 或查询参数为空时的实际语义。
- [ ] 检查跨表写操作是否具备正确的事务边界。
- [ ] 检查批量逻辑是否存在循环内逐条查询数据库或远程接口。
- [ ] 检查外部接口失败、空响应或空列表是否被误判为成功。
- [ ] 检查新增或修改的方法、状态流转、事务、外部接口和复杂异常分支是否有说明业务原因和约束的注释。
- [ ] 检查注释、接口说明、状态名称和 SQL 说明是否与当前实现一致，不能保留旧流程或旧对象名称。

## 安全性

- [ ] 按 ID 访问数据时，校验当前用户、公司或租户的数据归属，防止越权访问或修改。
- [ ] 检查日志、异常和接口响应是否泄露密码、Token、身份证号等敏感信息。
- [ ] 检查新增配置和代码中是否出现明文密码、密钥或 Token。
- [ ] 检查新增字段的必填校验是否误伤其他合法消息类型或业务分支。

## 结果

- [ ] 执行与改动匹配的静态检查、单元测试或集成测试。
- [ ] 报告中区分本次修改范围和全项目范围，记录实际执行命令、通过项、失败项和未覆盖项，不能把局部通过表述为全项目通过。
- [ ] 交付前重新核对报告中的可点击链接、当前行号和方法或区块名称，确保能够直接定位本次修改内容。
- [ ] 发现问题时先修复，再重新执行相关检查，不得在审查未通过时汇报完成。
