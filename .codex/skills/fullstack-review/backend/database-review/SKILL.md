# Database Review

审查数据库引擎、表结构、SQL、索引、事务、并发、迁移和数据一致性。先确认实际数据库类型、版本、驱动、部署方式、数据量和变更环境；没有证据时标记待确认，不把某一种数据库的行为套用到其他数据库。

## 审查流程

1. 识别实际数据库引擎、版本、驱动、字符集、排序规则、连接配置和迁移工具。
2. 找到相关表、字段、约束、索引、SQL、事务入口、迁移脚本和回滚方案。
3. 区分数据库通用问题和引擎特有问题，引用实际 DDL、执行计划、日志或数据结果。
4. 检查应用新旧版本与数据库变更的兼容顺序。
5. 输出问题、影响、修复方向、验证命令、回滚限制和未覆盖项。

## 审查范围

### 1. 表结构和数据类型

- 表、字段、索引、约束、外键、视图和触发器命名是否统一，含义是否清晰。
- 主键、唯一约束、非空、默认值、删除策略和状态字段是否表达真实业务规则。
- 数值精度、金额、数量、时间、时区、枚举、JSON、二进制和大文本字段是否匹配实际范围。
- 字符集、排序规则、大小写敏感性、长度计算和跨数据库迁移差异是否明确。
- 新增或调整字段是否有字段注释；新建表时是否为全部字段提供注释。
- 自增、序列、身份列、UUID 和分布式主键是否满足唯一性、排序性和迁移要求。

### 2. SQL 正确性

- 查询条件、连接条件、空值语义、聚合、分组、排序、分页和返回字段是否符合业务语义。
- 左连接、重复行、去重、集合运算和子查询是否可能改变结果数量或结果含义。
- 空集合、空参数、边界日期、时区、精度、隐式类型转换和大批量参数是否有明确语义。
- 分页排序是否稳定；深分页、游标分页和并发写入下是否可能漏数据或重复数据。
- 是否使用了当前数据库支持的语法，避免把 MySQL、PostgreSQL、Oracle、SQL Server 或 SQLite 语法混用。
- 更新和删除是否具备明确条件、影响行数检查和误操作保护。

### 3. 索引与性能

- 索引列顺序是否匹配主要过滤、连接、排序和选择性；不要只按字段数量判断索引质量。
- 是否存在全表扫描、无效索引、函数包列、隐式类型转换、前缀模糊查询和不必要的回表。
- 是否使用当前引擎的执行计划工具，例如 EXPLAIN 或安全条件下的 EXPLAIN ANALYZE。
- 性能结论是否基于真实数据量、统计信息、执行计划和基线，不以单条样例数据推断生产性能。
- 批量读写、排序、聚合、临时表、内存使用和大结果集是否可能造成资源耗尽。
- 新增索引是否评估写入成本、空间成本、构建锁、重复索引和线上变更时间。

### 4. 事务、并发和锁

- 事务边界是否覆盖必须原子完成的写操作；跨表失败时是否能正确回滚。
- 隔离级别、快照、锁类型、锁顺序、死锁重试、超时和长事务风险是否符合业务要求。
- 库存、余额、额度和状态流转是否具备条件更新、版本控制、唯一约束或其他一致性措施。
- 查询后再写入的逻辑是否存在竞态；幂等键是否真正阻止重复数据。
- 连接池、事务超时、批量提交和大事务是否可能占满数据库资源。

### 5. 迁移、兼容和回滚

- 迁移脚本是否说明目标数据库、执行前提、业务目的、历史数据处理、重复执行语义和锁影响。
- 新旧应用版本是否能在迁移期间同时运行；字段新增、重命名、删除和类型调整是否遵循兼容顺序。
- 大表回填、索引创建、数据修复和删除操作是否可分批、可暂停、可观测。
- 回滚是否真实可执行；不可逆的数据删除、类型收窄和默认值变化是否明确说明。
- 迁移失败、部分成功、重复执行和超时后的恢复路径是否经过验证。

### 6. 数据安全与治理

- SQL、脚本和配置中是否存在明文密码、密钥、Token 或连接凭据。
- 读取、修改、删除、导出和下载是否落实用户、组织、租户和资源归属。
- 敏感字段是否有最小权限、脱敏、加密、审计、保留期限和备份恢复要求。
- 数据库错误、执行计划、参数和结果日志是否泄露敏感数据或内部结构。
- 数据库账号、网络访问、管理端点和高权限操作是否符合最小权限原则。

## 数据库引擎专项

只在项目实际使用对应引擎时检查以下内容：

- MySQL：存储引擎、InnoDB 事务、字符集和排序规则、utf8mb4、在线 DDL、自增行为、执行计划和深分页。
- PostgreSQL：MVCC、事务型 DDL、类型系统、数组和 JSON、部分或表达式索引、序列和锁等待。
- Oracle：NUMBER 精度、日期时间类型、序列或身份列、空字符串语义、事务行为、执行计划和迁移窗口。
- SQL Server：身份列、聚集和非聚集索引、锁升级、隔离级别、日期时间类型和执行计划。
- SQLite：类型亲和性、写并发、事务模式、外键启用状态、迁移限制和文件级资源管理。

## 边界

- MyBatis、JPA/Hibernate、JDBC、Mapper 和 Repository 实现读取 data-access-review。
- Java 集合、线程池和异常实现读取 java-review。
- Spring 事务代理、配置、缓存和消息整合读取 springboot-review。
- 注入、越权、敏感信息和租户隔离读取 security-review。
- 数据变更后的接口、页面和回归用例读取 test-generation。

## 清单联动

清单路径解析：CHECKLIST_ROOT 先解析为当前项目/.codex/checklists/；不存在时再解析为 ~/.codex/checklists/fullstack-quality-kit/。本节中的 code-review/、business-test/、db-change/ 和 external-api-doc/ 路径均相对于 CHECKLIST_ROOT；CHECKLIST_ROOT 仅是逻辑标识，不要求设置环境变量。

- 写入 SQL、DDL、迁移或数据库配置时，读取 CHECKLIST_ROOT/CODE_REVIEW_CHECKLIST.md、code-review/code-quality-baseline.md 和 code-review/database-quality.md。
- 执行数据写入、删除、结构变更或可能造成锁等待的操作时，读取 CHECKLIST_ROOT/DB_CHANGE_CHECKLIST.md，并按范围读取 db-change/ 子清单。
- 数据变化影响接口、页面或状态时，读取 CHECKLIST_ROOT/BUSINESS_TEST_CHECKLIST.md 及相关 business-test/ 子清单。
- 用户明确要求整理或生成外部接口文档时，读取 CHECKLIST_ROOT/EXTERNAL_API_DOC_CHECKLIST.md 及相关 external-api-doc/ 子清单。

## 输出要求

每个数据库问题必须指出具体对象、语句或迁移步骤、触发条件、证据、影响范围、修复方向和验证方式。索引和性能问题必须说明所需执行计划、数据量或基线；不能只写“加索引”或“优化 SQL”。
