# 设计上下文工作流

## 用途

在新增 Skill、清单、路由或调整工具集结构前，形成可确认的设计方案，避免新内容重复、越界或削弱现有职责。

## 触发条件

- 新增 Skill。
- 新增、拆分、合并或调整清单。
- 修改 fullstack-review 路由。
- 调整工具集目录结构。
- 需要记录职责边界、术语或架构决策。

## 执行步骤

1. 读取主 Skill、相关专业子 Skill、相关总清单和领域子清单。
2. 检查安装、卸载、验证和使用文档。
3. 识别现有能力边界、调用链、重复风险和兼容性风险。
4. 形成设计方案，明确哪些内容保持不变。
5. 默认只输出方案，不修改文件。
6. 修改前说明目标文件、具体变更、影响范围、风险和回滚方式，并取得用户明确确认。

## 设计方案内容

设计方案至少包含以下内容：

- 目标。
- 适用场景。
- 不适用场景。
- 输入。
- 输出。
- 触发条件。
- 不触发条件。
- 关联专业子 Skill。
- 关联总清单和领域子清单。
- 预计变更文件。
- 安装、卸载和验证影响。
- 兼容性风险。
- 回滚方式。
- 待确认事项。

## 边界

- 设计方案不等于修改授权。
- 不新增与用户目标无关的 Skill、清单、脚本或目录。
- 不用新的路由覆盖、合并或削弱既有专业子 Skill、总清单或领域子清单。
- 如当前环境存在额外设计能力，可作为辅助；本工作流不以外部 Skill 为硬依赖。

## 完成条件和回退

用户确认方案后，返回 fullstack-review 主流程，按实际技术范围继续路由、修改和验证。用户未确认时只保留设计结论和待确认事项。
