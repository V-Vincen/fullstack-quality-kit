# 需求澄清工作流

## 用途

当用户目标、范围、授权或验收标准不足以安全执行时，先澄清需求，再回到主流程继续路由。

## 触发条件

- 用户目标不明确。
- 审查或修改范围不明确。
- 用户要求新增 Skill、清单或路由，但没有说明边界。
- 用户没有说明是否允许修改文件。
- 用户没有说明最终需要报告、测试用例、设计方案还是代码修改。

## 不触发条件

- 用户已明确指定目标文件、模块、范围、权限和验收标准。
- 用户只要求只读审查。
- 用户只要求执行已有验证命令。

## 执行规则

1. 最多提出 5 个会影响执行方向的问题，不把可以通过只读检查确认的事项交给用户回答。
2. 按目标、范围、是否允许写入、涉及技术领域、验收标准的顺序优先澄清。
3. 不因澄清自行扩大任务范围，不把用户未授权的修改、安装、部署或外部操作视为已授权。
4. 用户未回答的事项必须标记为“待确认”，不能以假设替代确认。
5. 本阶段默认只读，不写入文件、不执行外部状态变更。
6. 当前环境存在 `grilling` 等额外澄清能力时可作为辅助；该工作流本身不依赖任何外部 Skill。

## 输出格式

~~~text
任务目标：
本期范围：
非本期范围：
涉及技术领域：
是否允许写入：
验收标准：
待确认事项：
~~~

## 完成条件和回退

当目标、范围、授权和验收标准已足够明确时，停止提问并返回 fullstack-review 的正常路由流程。仍未明确的事项保留为“待确认”，不阻塞与其无关的只读分析。

## 边界

- 需求澄清不替代 AGENTS.md 的授权、备份、验证和交付规则。
- 需求澄清不替代总清单、领域子清单或专业子 Skill 的路由。
- 不把提出问题、收到部分回答或形成假设表述为修改授权。
